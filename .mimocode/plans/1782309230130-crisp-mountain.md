# Plano: Sistema de Alertas via WhatsApp (Baileys)

## Contexto

Adicionar um canal paralelo de notificação via WhatsApp ao sistema de alertas existente. O sistema atual já envia alertas internos + e-mail. O WhatsApp será um terceiro canal, seguindo o mesmo padrão arquitetural (fire-and-forget com fila de retry).

**Requisitos**: sem custos, apenas envio, simples, não destrutivo.

## Desafio Central

Baileys requer uma conexão WebSocket persistente com servidores WhatsApp. Em Vercel (serverless), funções são efêmeras — não dá para manter a conexão. Solução: **serviço WhatsApp separado** (Docker/VPS) com API HTTP que o Next.js chama.

## Arquitetura

```
Next.js (Vercel)                        Serviço WhatsApp (separado)
┌──────────────────────┐                ┌──────────────────────────┐
│ notification-events  │   POST /send   │ Express + Baileys        │
│   sendWhatsApp() ─────────────────────►│ WebSocket → WhatsApp     │
│   queueWhatsApp()    │                │ Rate limit: 1 msg/seg    │
│                      │                │ QR code auth (1x)        │
│ whatsappQueue ───────┼── cron retry ──│                          │
└──────────────────────┘                └──────────────────────────┘
```

## Fluxo de Envio

1. Evento dispara (tarefa criada, estágio mudou, prazo próximo, etc.)
2. `notification-events.ts` chama `sendWhatsApp()` para cada destinatário
3. `sendWhatsApp()` tenta POST para a API do serviço Baileys
4. Sucesso → pronto
5. Falha → `queueWhatsAppMessage()` grava em `whatsappQueue`
6. Cron `process-whatsapp` retenta mensagens pendentes (max 3 tentativas)

## Serviço WhatsApp Externo (referência)

O usuário precisará rodar um serviço Baileys separado. Exemplo mínimo:

```
whatsapp-service/
├── package.json
├── src/
│   ├── index.ts          # Express server
│   ├── baileys.ts        # Conexão Baileys
│   └── auth.ts           # QR code + session
└── Dockerfile
```

Endpoints do serviço:
- `POST /send` — `{ phone, message }` → envia mensagem
- `GET /status` — verificar se está conectado
- `GET /qr` — obter QR code para autenticação

**Nota**: O serviço externo fica fora do escopo deste plano. O Next.js apenas chama a API HTTP dele.

# Data Model: Sistema Kanban Jurídico Interno

## Conventions

- All timestamps use server-generated values.
- All protected writes record `createdBy`, `createdAt`, and when mutable,
  `updatedBy`, `updatedAt`.
- IDs are opaque strings generated by the data layer.
- User-facing references use `referenceCode`, not document IDs.
- Critical collections are append-only in normal workflows: task history and
  audit logs.

## Collections

### users/{userId}

Represents an authenticated internal user profile.

Fields:

- `displayName`: string, required
- `email`: string, required, unique by Firebase Auth identity
- `roleId`: string, required
- `status`: `active | disabled`, required
- `permissions`: string[], optional overrides for specific permissions
- `createdAt`, `createdBy`, `updatedAt`, `updatedBy`

Relationships:

- Belongs to one role.
- May be responsible for many tasks.
- May receive many alerts.

Validation:

- Only administrators can create, disable or change role/permissions.
- Disabled users cannot access private app data.

### roles/{roleId}

Represents a permission group.

Fields:

- `name`: `administrator | coordinator | collaborator | internal_reader`
- `label`: string
- `permissions`: string[]
- `description`: string
- `active`: boolean

Validation:

- Initial roles must exist before pilot use.
- Permission changes are critical audit events.

### workflowStages/{stageId}

Represents a Kanban column/stage.

Fields:

- `label`: string
- `order`: number
- `type`: `active | completed | archived`
- `isInitial`: boolean
- `isTerminal`: boolean
- `allowedTransitions`: string[]
- `requiresCommentToEnter`: boolean
- `active`: boolean

Initial stages:

1. Entrada
2. Em análise
3. Aguardando documentos
4. Em andamento
5. Em revisão
6. Concluída
7. Arquivada

Validation:

- A task can move only to an allowed transition.
- Arquivada accepts only completed tasks or authorized administrative closure.

### tasks/{taskId}

Represents a legal task in the Kanban flow.

Fields:

- `referenceCode`: string, required
- `title`: string, required
- `description`: string, required
- `category`: string, required
- `priority`: `low | normal | high | urgent`, required
- `stageId`: string, required
- `responsibleUserId`: string, required
- `participantUserIds`: string[], default []
- `createdBy`: string, required
- `createdAt`: timestamp, required
- `updatedBy`: string
- `updatedAt`: timestamp
- `dueAt`: timestamp, optional
- `dueStatus`: `none | upcoming | overdue`, derived/stored for filtering
- `confidentialityLevel`: `standard | restricted`, required
- `internalNotes`: string, optional
- `archived`: boolean, default false
- `completedAt`: timestamp, optional
- `archivedAt`: timestamp, optional
- `archivedBy`: string, optional
- `restoredAt`: timestamp, optional
- `searchText`: string, normalized for basic title/reference search

Relationships:

- Has many history events, comments and attachments.
- Generates many alerts and audit logs.

Validation:

- Required fields must be present on creation.
- Only authorized roles can create or edit.
- Stage changes go through workflow service only.
- Archived tasks are read-mostly; edits require administrative permission.

### tasks/{taskId}/history/{historyId}

User-facing chronological history for a task.

Fields:

- `eventType`: `created | edited | stage_changed | responsible_changed |
  comment_added | attachment_added | completed | archived | restored |
  returned_to_previous_stage`
- `actorUserId`: string
- `actorRoleId`: string
- `occurredAt`: timestamp
- `previousValue`: object, optional
- `newValue`: object, optional
- `summary`: string
- `relatedCommentId`: string, optional
- `relatedAttachmentId`: string, optional

Validation:

- Append-only in ordinary use.
- Created by domain services, not direct UI mutation.

### tasks/{taskId}/comments/{commentId}

Internal task comment.

Fields:

- `body`: string, required
- `mentionedUserIds`: string[], default []
- `createdBy`: string
- `createdAt`: timestamp
- `editedAt`: timestamp, optional
- `deletedAt`: timestamp, optional administrative soft-delete

Validation:

- Author must have permission to view/comment on task.
- Mentions create alerts for mentioned users with task access.

### tasks/{taskId}/attachments/{attachmentId}

Metadata for a task attachment.

Fields:

- `fileName`: string
- `contentType`: string
- `sizeBytes`: number
- `storagePath`: string
- `uploadedBy`: string
- `uploadedAt`: timestamp
- `status`: `active | quarantined | removed`
- `description`: string, optional

Validation:

- Storage path must be under `tasks/{taskId}/attachments/{attachmentId}/`.
- File access requires permission to view the task.
- Removal is metadata-controlled and audited.

### alerts/{alertId}

Internal notification record.

Fields:

- `recipientUserId`: string
- `taskId`: string
- `eventType`: `task_created | responsible_changed | stage_changed |
  due_upcoming | due_overdue | completed | archived | comment_mention |
  returned_to_previous_stage`
- `title`: string
- `message`: string
- `createdAt`: timestamp
- `readAt`: timestamp, optional
- `triggeredBy`: string, optional
- `dedupeKey`: string
- `emailRequired`: boolean
- `emailStatus`: `not_required | queued | sent | failed`

Validation:

- One active alert per recipient and dedupe key.
- Alert must include enough task context for the recipient to act.

### emailQueue/{emailJobId}

Represents a pending or completed e-mail notification job.

Fields:

- `alertId`: string
- `recipientUserId`: string
- `recipientEmail`: string
- `template`: string
- `status`: `queued | sending | sent | failed`
- `attempts`: number
- `lastError`: string, optional
- `createdAt`, `updatedAt`

Validation:

- E-mail job must reference an internal alert.
- E-mail failure does not remove the internal alert.

### auditLogs/{auditId}

Protected audit trail for critical events.

Fields:

- `actorUserId`: string, optional for failed login if unknown
- `actorRoleId`: string, optional
- `action`: string
- `resourceType`: `auth | user | role | task | comment | attachment |
  alert | archive | workflow`
- `resourceId`: string, optional
- `result`: `success | denied | failed`
- `occurredAt`: timestamp
- `requestId`: string
- `metadata`: object

Validation:

- Append-only.
- Readable only by administrators and explicitly authorized audit readers.
- Created by trusted server-side code.

## State Transitions

Default stage transitions:

- Entrada -> Em análise, Aguardando documentos
- Em análise -> Aguardando documentos, Em andamento, Em revisão
- Aguardando documentos -> Em análise, Em andamento
- Em andamento -> Aguardando documentos, Em revisão, Concluída
- Em revisão -> Em andamento, Concluída
- Concluída -> Arquivada, Em revisão
- Arquivada -> Concluída only by authorized restore flow

Rules:

- Any backward transition creates `returned_to_previous_stage` history and alert.
- Configured transitions may require comment.
- Arquivada requires Concluída or administrative closure.
- Every transition creates task history, audit log and relevant alerts.

## Index Needs

- `tasks`: `archived + stageId + priority`
- `tasks`: `archived + responsibleUserId + dueStatus`
- `tasks`: `archived + category + updatedAt`
- `alerts`: `recipientUserId + readAt + createdAt`
- `auditLogs`: `resourceType + resourceId + occurredAt`
- `auditLogs`: `actorUserId + occurredAt`

Exact Firestore index definitions are implementation tasks after query shapes
are finalized.
